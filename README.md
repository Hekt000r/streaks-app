# Streaks

A personal Android habit tracker built with React Native and Expo, backed by an offline Kotlin/Room engine. Complete small promises, build streaks, earn freezes, and let increasingly persistent reminders bring you back.

## What is implemented

- Daily/weekday check-offs and integer numeric goals, with today-only progress corrections.
- Current/best streaks, recent calendar history, and per-habit freezes: earn one every seven completions, hold two, automatically protect a miss.
- Native escalating notifications, Done/+1/Snooze actions, quiet hours, and a global daily alert cap.
- Onboarding, Today, habit management, habit details/editor, and settings.
- Completion animations, haptics, an original chime, and accessible/reduced-motion controls.
- JSON backup export/import through the Android document/share interfaces.
- Local release signing, Android CI configuration, unit/instrumentation tests, and a device acceptance checklist.

## Run on Android

Requires Node22 (see `.nvmrc`), JDK17, Android SDK platform36/build-tools36.0.0, and Android8/API26 or newer. Set `ANDROID_HOME` to your SDK installation. Use an emulator or enable USB debugging on a phone.

```bash
npm ci
npx expo install --check
npm run android
```

The resolved `package-lock.json` is included. Use `npm ci` for reproducible installs; dependencies follow Expo SDK54's bundled compatibility matrix. In this workspace, per-user Node22/JDK17/Android SDK tools have also been installed: `source scripts/toolchain-env.sh` adds them to the current shell without changing your system installation.

Use `npm start` to start Metro for an existing development build. **Expo Go cannot load the Kotlin habit engine.** Android native files are generated by Expo prebuild; the maintained module lives under `modules/streak-engine/android/` and is discovered through local Expo autolinking.

## Build a standalone APK

```bash
npm run build:apk
```

The script runs JS/type/UI checks, generates Android files, runs native unit tests, and assembles `dist/streaks.apk`. It creates a private signing key in ignored `.signing/` on first use. Keep that directory backed up securely: installing updates without deleting data requires the same signing key. For an existing key, supply `STREAKS_KEYSTORE` (absolute path), `STREAKS_STORE_PASSWORD`, `STREAKS_KEY_ALIAS`, and `STREAKS_KEY_PASSWORD`. Release builds fail if signing credentials are absent rather than silently using Android's shared debug key.

The currently built `dist/streaks.apk` is a signed **ARM64** APK (46MB), suitable for modern Android phones running Android8 or newer. It includes its JavaScript bundle and runs without Metro. Its checksum is in `dist/streaks.apk.sha256`. Reproduce this variant with `npm run build:apk -- -PreactNativeArchitectures=arm64-v8a`; omit that argument to build all default architectures. Builds use two Gradle workers and a larger compiler metadata limit; `STREAKS_GRADLE_WORKERS` and `STREAKS_GRADLE_JVMARGS` can override those settings.

```bash
adb install -r dist/streaks.apk
```

The CI workflow compiles a development/debug APK and runs checks; its artifact is for development and needs Metro. The local release script produces the standalone, offline APK.

## Behavior details

Streaks count **scheduled successes**, not elapsed calendar days. Unscheduled days are neutral. A frozen missed day preserves the streak without increasing it or earning another freeze. Editing weekdays/targets takes effect tomorrow; names, icons, colors, and reminder times update immediately. Reminder cutoff ends notifications, while today's progress can still change until local midnight.

Default reminders run09:00–22:00: every two hours, hourly in the final three hours, and every30minutes in the final hour. Simultaneously due habits are bundled; at most12 alerts are posted per local day across the app. Snooze lasts30minutes. Settings can change the cap and quiet hours; matching quiet start/end disables quiet hours. Disabled app/channel notifications are shown in Settings.

Android can delay inexact alarms in Doze or manufacturer battery modes. Force-stopping the app requires reopening it before reminders resume. There are no exact-alarm permissions, continuous foreground service, remote push provider, or JavaScript background timer.

## Data and architecture

React Native renders data and submits commands through a typed Expo module. The Kotlin repository owns all domain writes in Room transactions, including notification actions. A single serialized aggregate row avoids competing JS/native databases. Historical dates and occurrence targets are retained; snapshots expose the last90 occurrences per habit, while backups retain full history. Future schema changes must add Room migrations—destructive fallback is disabled.

Data is stored in app-private storage. There is no account, cloud service, advertising SDK, or analytics. Android automatic cloud backup is disabled. Exported JSON is unencrypted and should be saved privately. Import validates the entire versioned backup before replacing data atomically, then rebuilds reminders. Import resets transient reminder snoozes and daily dispatch state. Uninstalling without an exported backup loses history.
